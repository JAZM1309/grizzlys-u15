ERGEBNIS-PUSH UND 24h-ERINNERUNG ALS CLOUD FUNCTIONS
=====================================================

Neu:
  onResultWritten    -> sendet den Ergebnis-Push SOFORT nach dem Speichern im Admin-Bereich
  sendGameReminders  -> prüft alle 10 Minuten (Google Cloud Scheduler) und sendet die 24h-Erinnerung
Beide beachten die Push-Auswahl der Nutzer (Ergebnisse / Erinnerung, U15 A / U15 B).
Geräte ohne gespeicherte Auswahl bekommen weiterhin alles.

Geänderte/neue Dateien im Repo
  functions/push.js        (neu)
  functions/index.js       (am Ende 3 Zeilen ergänzt)
  functions/package.json   (Node 22)
  firebase.json            (Runtime nodejs22)

SCHRITT 1 – Dateien ins GitHub-Repo
  Die vier Dateien oben ins Repo hochladen (push.js liegt im Ordner functions).

SCHRITT 2 – Deploy in der Cloud Shell
  1. https://console.cloud.google.com öffnen, oben das Projekt grizzlys-u15 wählen,
     oben rechts auf das Symbol "Cloud Shell aktivieren" (>_) tippen.
  2. Einmalig bzw. bei Änderungen den Code holen:
       cd ~ && rm -rf grizzlys-u15 && git clone https://github.com/jazm1309/grizzlys-u15.git
       cd grizzlys-u15/functions && npm install && cd ..
     (Ist das Repo privat, nach Benutzername und GitHub-Token fragen lassen.)
  3. Anmelden und deployen:
       firebase login --no-localhost        (nur falls nach Login gefragt wird; Link öffnen, Code einfügen)
       firebase deploy --only functions --project grizzlys-u15
     Fragt Firebase nach dem Aktivieren von "Cloud Scheduler" oder anderen APIs: mit y bestätigen.
     Mit "--only functions" werden alle Functions auf Node 22 umgestellt (Frist 30.10.2026).
     Wer nur die neuen deployen will:
       firebase deploy --only functions:onResultWritten,functions:sendGameReminders --project grizzlys-u15

SCHRITT 3 – Prüfen
  - Firebase Console > Functions: onResultWritten und sendGameReminders stehen in der Liste.
  - Google Cloud Console > Cloud Scheduler: ein Job "firebase-schedule-sendGameReminders-..." existiert.
    Dort "Job jetzt ausführen" tippen, danach in Logs (Cloud Run / Functions > Protokolle) prüfen,
    dass keine Fehler stehen (Meldung "Erinnerung: niemand angemeldet" oder nichts ist normal,
    solange kein Spiel in 23-25 Stunden ansteht).
  - Der echte Test des Ergebnis-Push ist das nächste eingetragene Ergebnis; im Protokoll steht
    dann "Ergebnis-Push" mit Zahl der Empfänger.

SCHRITT 4 – GitHub-Workflow abschalten (erst nach bestandenem Test)
  GitHub > Actions > "Grizzlys Ergebnisdienst" > drei Punkte > Disable workflow.
  Beide Varianten dürfen kurz parallel laufen: Sie verwenden dieselben Duplikatsperren
  (results.pushSentAt und gameReminders), es wird also nichts doppelt gesendet.
  Zurück auf den alten Weg: Workflow wieder aktivieren, die Functions können bleiben oder
  mit "firebase functions:delete onResultWritten sendGameReminders --region europe-west1" entfernt werden.

Danach nicht mehr nötig: GitHub-Secret FIREBASE_SERVICE_ACCOUNT (außer für den Bug-Workflow, falls er aktiv bleibt).


EHV-DATEN ALS CLOUD FUNCTIONS (ab Version 1.9.0)
================================================

Neu:
  standings      -> liefert der App Tabellenstand und beendete Spiele beider Ligen (U15 A: 21652, U15 B: 21656).
                    Holt die Daten höchstens alle 30 Minuten vom EHV, antwortet nur der App (jazm1309.github.io).
  autoResults    -> trägt alle 30 Minuten beendete Grizzlys-Spiele als Ergebnis ein. Der Ergebnis-Push geht wie bei
                    einem Handeintrag raus, aber nur für Spiele der letzten 2 Tage. Handeinträge werden nie überschrieben.
  scheduleWatch  -> vergleicht alle 3 Stunden den Spielplan der App mit dem des EHV und meldet NEUE Abweichungen
                    per Push an die Admin-Geräte. Merkt sich den Stand in Firestore unter ehvSync/scheduleWatch.
  scheduleCheck  -> derselbe Vergleich auf Knopfdruck im Admin-Bereich ("Mit EHV-Spielplan abgleichen"). Liest nur.

Dateien im Repo
  functions/standings.js   (neu)
  functions/ehv-sync.js    (neu)
  functions/index.js       (am Ende 4 Zeilen ergänzt)

Deploy in der Cloud Shell (im Ordner mit firebase.json)
  firebase deploy --only functions:standings,functions:autoResults,functions:scheduleCheck,functions:scheduleWatch --project grizzlys-u15

Schalter in functions/ehv-sync.js
  AUTO_RESULT_PUSH = true        false = automatische Ergebnisse immer ohne Push eintragen
  RESULT_PUSH_MAX_AGE_DAYS = 2   ältere, nachgetragene Ergebnisse lösen keinen Push aus

Hinweise
  - Der Zugriffsschlüssel in standings.js ist der öffentliche Schlüssel der EHV-Seite. Ändert der Verband ihn,
    bleiben Chips, Form und Drittel in der App einfach weg; der Spielplan läuft normal weiter.
  - Ein automatisch eingetragenes Ergebnis hat das Feld source: "ehv". Wird es im Admin-Bereich von Hand neu
    gespeichert, geht der Ergebnis-Push (erneut) raus.
  - Wichtig: Wer die Functions nach SCHRITT 2 oben neu aus dem Repo holt (git clone), braucht diese drei Dateien
    im Repo – sonst fehlen die EHV-Functions beim nächsten Deploy.


NEWS-HINWEISE MIT OPTIONALEM PUSH (ab Version 1.9.1)
====================================================

Neu:
  onNewsCreated  -> wird ausgelöst, wenn im Admin-Bereich unter "Hinweise / News" ein Hinweis veröffentlicht wird.
                    Nur wenn der Haken "Zusätzlich als Push senden" gesetzt ist, geht ein Push an alle angemeldeten
                    Geräte. Bei einem Hinweis nur für U15 A oder U15 B gilt die Mannschaftsauswahl der Geräte.
                    Jeder Hinweis wird höchstens einmal verschickt (Feld pushSentAt).

Dateien im Repo
  functions/news.js        (neu)
  functions/index.js       (am Ende 1 Zeile ergänzt)
  firestore.rules          (neue Sammlung "news": für alle lesbar, nur Admin schreibt)

Veröffentlichen in der Cloud Shell (im Ordner mit firebase.json, z. B. ~/grizzlys-u15)
  Wichtig: die Regeln MÜSSEN veröffentlicht werden, sonst kann der Admin-Bereich keine Hinweise speichern
  und die App zeigt keine an.
    firebase deploy --only firestore:rules,functions:onNewsCreated --project grizzlys-u15

Prüfen
  - Firebase Console > Functions: onNewsCreated steht in der Liste.
  - Firebase Console > Firestore > Regeln: der Block "match /news/{newsId}" ist enthalten.
  - Im Admin-Bereich der Live-App einen Test-Hinweis ohne Push veröffentlichen -> erscheint im News-Fenster;
    danach wieder löschen. (Die Testversion kann Hinweise nur anzeigen, nicht speichern.)


TEST-PUSH AN DEN ADMIN (ab Version 1.9.1.90)
============================================

Neu:
  adminPushTest  -> wird im Admin-Bereich unter "Push-Status" ausgelöst und schickt einen Test-Push an alle
                    Geräte, die als Admin registriert sind. Nur der angemeldete Admin darf die Function aufrufen.
                    "In 10 Sekunden senden" wartet vor dem Versand, damit man die App in den Hintergrund legen kann.
                    Meldet Firebase ein Token als ungültig, wird der Eintrag in pushTokens gelöscht.

Dateien im Repo
  functions/pushtest.js    (neu)
  functions/index.js       (am Ende 1 Zeile ergänzt)

Veröffentlichen in der Cloud Shell
  pushtest.js über das Drei-Punkte-Menü hochladen, dann:
    mv ~/pushtest.js ~/grizzlys-u15/functions/
    cd ~/grizzlys-u15 && firebase deploy --only functions:adminPushTest --project grizzlys-u15
  (Die Zeile in index.js nur ergänzen, falls sie dort noch fehlt:
    exports.adminPushTest = require("./pushtest").adminPushTest; )

Prüfen
  - Admin-Bereich > Push-Status > "Test-Push sofort senden": bei offener App erscheint eine grüne Bestätigung.
  - "In 10 Sekunden senden" und zum Startbildschirm wechseln: die Benachrichtigung "Test-Push ✓" erscheint.
  - Kommt nichts an, obwohl "gesendet" angezeigt wird: in den Einstellungen "Push kommt nicht an? Neu einrichten"
    antippen (erneuert Push-Abo und Token) und den Test wiederholen.
